范围与运行状态
类型发现、后端摘要/计数、原有 image 校验、默认预览选择和热加载统一走类型声明。

声明接口
内置扫描根是 hololab/；随 wheel 分发 hololab/types/*。用户扫描根来自现有 pack_scan_dirs。
扫描 <root>/types/*/manifest.yaml，不按类型名建立源码白名单。目录名不决定注册名。
用户根按配置顺序先到先得，随后加载内置根；重复名字采用首个声明。
kind: Type（可省略）声明单个类型；kind: TypeSet + types 列表可以在一个文件声明多个类型。
内置类型一个类型一个目录。类型定义无效/不可读时跳过，不新增产物校验、strict 模式或违规计数。

最小例子：
  kind: Type
  name: custom
  element: file
  summary: summary.py:summary
  preview:
    viewer: iframe
    entry: viewer/index.html

  # summary.py
  def summary(path, storage):
      # path 是 pathlib.Path；storage 是 "file" 或 "dir"。
      return {"kind": "custom", "fields": {"format": "custom"},
              "counts": {"count": 3, "kind": "items",
                         "items": [{"label": "item", "value": 3}]}}

summary 返回 JSON dict 或 None。字段/计数均可选；不认识返回 None。
counts 的 count/kind 保留旧标量协议；items 非空时沿用旧 internal_count_items 协议。
summary 在可终止子进程内运行，2 秒期限包含启动/导入/执行，报错、超时或非 JSON 返回值均降级为未测量。
每次运行类型局部 helper 从源码加载，避免秒级 pyc 时间戳导致同长度编辑失效。
summary_role: counts 表示仅对采样叶计数；summary_role: fields 表示只负责根摘要。
未指定 role/dispatch 的新类型按 tag 名匹配摘要，不需编辑平台分派代码。
dispatch 的 order/storage/tags/suffixes/case_sensitive 保留历史根摘要的选择顺序。
content_dims: {count: N} 声明内在维数；summary 返回 content_dims: [尺寸...]。未测量仍返回 None。
element 是形态声明，不自动引入新校验。image 的 check_declaration/validate_leaf 是原有检查的原样迁移。

预览协议
preview.viewer 可以引用现有 React renderer；这些 renderer 的布局、分页、交互实现继续复用。
preview.entry 指向类型目录的 HTML，走 /api/types/{name}/assets/{path}，相对资源可一并放入目录。
NodeViewerFrame 仍发送 hololab-viewer-state（viewer_id、frames、history_url、running、progress 等）。
类型资产带 generation URL，HTTP no-store，目录越界访问返回 404。
preview_rule 声明历史覆盖优先级：order、storage、when、override（missing/text/any）和 preview。
历史 image/rig/colmap 抢占以及二进制数据覆盖旧 text 的规则已迁入声明；不是新加优先级。
preview_terminal 保留原先优先于其它拦截的 renderer；preview_fallback 保留错误 storage 时原有未注册 viewer 降级。
浏览器不再拥有 FRONTEND_VIEWER_TAGS，也不按 tag 改写下发的 viewer。

热加载链路
现有 pack watcher 同时监视内置 types 和各 pack 根；源文件或声明变化触发原有 packs_updated/node_online 通道。
/api/packs/reload 复用同一重扫函数。PacksUpdated.type_roots 同步运行中变更的扫描根。
声明/实现/资产内容参与类型 generation；请求入口也检查文件变化。
HandleSummaryCache、持久化 handle_facts 和浏览器 handle/edge facts 缓存按 generation 失效。
catalog 附带 type_generation；不修改 pack manifest hash 或代码身份。
同一 pack hash、同一 handle 的已打开预览会重新取元数据，类型资产变化会改变 iframe URL。
旧持久化 facts 初次读取进入 pending 并按原有后台机制补测；不会修改产物本身。
