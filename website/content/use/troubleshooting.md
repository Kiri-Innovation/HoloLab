# 排错

先分清是界面没有连接到网关、计算设备离线，还是某个算法任务失败。不要因为画布上有红色状态就反复提交同一个任务。

## 界面打不开

检查启动终端是否仍在运行，以及是否报告端口占用。默认端口是 8828；指定其他端口后，浏览器地址也要一起修改。

使用 `--host 127.0.0.1` 启动时，只能从本机访问。远程浏览器访问还取决于监听地址、网络和端口配置。

## 找不到 Pack 或无法运行

- 先看 **Compute nodes** 中设备是否在线，再看 **Packs** 的搜索词是否把它过滤掉。
- 打开设备设置检查 **Pack sources**；添加的是计算设备上的路径。
- manifest 无法解析时，扫描可能跳过该 Pack。检查计算节点日志和 manifest，而不是不断刷新页面。
- 提示 `unassigned` 时，为节点选择计算设备；提示缺少必填输入时补齐连线。
- 连线提示不兼容时，核对类型、集合层数和轴名。连接成功也不保证数据内容符合算法要求。

## 运行状态是什么意思

| 界面状态 | 接下来怎么处理 |
| --- | --- |
| 等待执行 / 已分配，等待启动 | 任务尚未开始，查看设备和任务队列，不必重复提交。 |
| 正在运行 | 查看进度与日志。没有进度百分比也可能仍在执行。 |
| 已主动停止 | 收到了停止指令，未成功完成；系统没有记录具体操作者。需要时重新运行。 |
| 执行设备失去连接 | 任务可能还在设备上运行。先检查连接，等待状态同步，避免重复计算。 |
| 运行中断（未恢复） | 重连后没有认领任务，或失联超时未恢复。确认设备与残留进程后再运行。 |
| 运行失败 | 查看日志中的失败原因，处理后再试。 |

失败原因中的 `oom` 表示执行端报告内存或显存不足；`user_error` 指向参数或输入；`system_error` 指向执行环境或系统；`algo_error` 表示算法进程异常退出。具体原因以日志为准。

## 改了参数，为什么还是旧结果

草稿与已提交任务是分开的。修改参数不会更新正在运行的进程，也不会让历史快照变成新参数的结果。等修改保存后，在草稿中运行需要更新的步骤。

如果提示工作流被另一个页面或客户端修改，先保留需要的修改信息，再重新加载最新版本；不要直接覆盖对方的修改。

## 预览失败或无法跳转文件

“产物已被清理”表示需要重新生成文件。设备离线、路径被手工移动或删除，也可能使预览失败。优先确认设备在线和文件仍在原位置。

跳转文件位置依赖 Flops Cobrowser 与设备映射，普通浏览器没有该入口。详细说明见[查看结果](results.md)。
