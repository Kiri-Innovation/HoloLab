# 用包身份与注册表固定算法依赖

> **开发中**：本节描述的能力尚在开发中，完成后此标记会移除。

同事打开一份工作流时，仅找到一个同名算法还不够：系统需要识别它的确切版本，并验证拿到的代码是否符合记录。包名、版本和哈希分别承担命名、契约和证据的职责。

## 从第一个包开始保留作用域

包使用 `scope/name@version` 身份，例如 `kiri/fastgs-silhouette-train@0.1.0`。公共库即使只有一个作用域，也保留作用域。

包名同时出现在 workflow 文件、快照记录和端口类型 tag 中。等历史数据积累后再补命名空间，意味着重写这些位置中的历史身份；从一开始保留作用域避免了这种迁移。

workflow 只允许精确版本，不使用范围版本。范围解析会使同一份配方在不同时间选择不同依赖，从而破坏“无 `+` 即有确定身份”的不变量。

## 哈希覆盖实际代码来源

包哈希按 Merkle 树覆盖以下内容：

- manifest；
- 包内代码；
- 每个声明依赖的**解析后身份**，包括外部仓库的 commit SHA、pip 依赖的实际版本。

算法代码可能来自 submodule 或外部仓库，并不都位于包目录。只哈希包目录，会让同一个 `name@version` 在上游代码不同的情况下仍得到相同证据，无法证明实际执行的是哪份代码。

**环境不进入哈希，但必须在 manifest 中声明。** Python、conda、CUDA 等运行时要求与显存、GPU 架构等硬件要求用于判断能否执行，不把频繁变化的运行环境当作代码身份。声明依赖的解析后身份仍参与哈希；这一点与排除执行环境本身不同。

**哈希是证据，版本是契约。** 哈希不参与类型兼容判断，也不参与缓存判定。因此，开发过程中改一行代码并不因为哈希变化就让全部下游变红。变量值改变触发的陈旧传播是另一条规则，不能由此省略。

## 开发版本可运行，快照记录当时的代码

`0.1.1+` 是合法、可运行的开发版本。末尾的 `+` 是纯标记，版本字符串不携带哈希。打快照时实时计算哈希，它在这里起本地迷你版本号、即 build 号的作用，区分同一个开发版本的不同代码状态。

**当 workflow 引用的所有包都不带 `+`（即都有确定哈希）时，该管线可复现。** 本文中的“可复现”仅指管线可重建，不保证数值或产物完全一致。带 `+` 的包可以运行，但不能仅凭这个版本标记声称其代码身份已经固定。

## 在 HoloLab 内完成发版

一键发版按顺序完成：**冻结外部依赖 → 计算哈希 → 落版本号 → 进入注册表**。发布版本把可变的开发状态变成可解析的确定身份。

注册表采用单一中央权威库，私有需求优先通过中央库的私有作用域承载。v1 使用静态索引与对象存储，不需要动态注册表服务；静态内容便于镜像和缓存，也减少服务故障面。发布由上传 tarball 和原子更新索引组成。自建源不属于这一阶段的交付范围，源配置与配方保持分离。

注册表遵守两条硬规则：

1. **已发布的 `name@version` 永久不可变。** 不允许以相同名字和版本重新上传另一份内容，否则版本与哈希的关系失去意义。
2. **允许 yank，不允许删除。** Yank 标记该版本不再推荐，但已记录的引用仍可解析。删除会让历史快照失去依赖。

## 配方写身份，本地配置决定去哪找

workflow 中只有 `kiri/fastgs-silhouette-train@0.1.0` 这样的包身份，不包含源地址。本地配置持有源列表，例如“私有源、公共源”。这与 `requirements.txt` 写依赖名字、`pip.conf` 决定从哪里获取的职责划分类似。

“去哪找”属于环境，不属于配方。这个边界使同一份 workflow 能在不同部署中使用：私有部署可以改变包的获取位置，而不改写工作流。

解析结果只有三类，不能把第三类降级为可忽略的提醒：

| 状态 | 处理 |
| --- | --- |
| 找到包，且哈希匹配 | 通过 |
| 找不到包 | 提示需要安装哪个包 |
| 找到包，但哈希不匹配 | **硬停**，不继续安装或运行不匹配的内容 |

## 发版补充历史证据，不覆盖历史

开发版本运行后再发版，不会把已经完成的快照改写成发布版本。哈希相等的发布版本通过 `published_as` 加注建立对应关系；原始版本和哈希仍保留。完整的历史与运行中例外见[快照与发版的衔接](/docs/contributor/variables-bindings-snapshots#发版怎样连接已有快照)。
