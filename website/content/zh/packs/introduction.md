# 发布算法包，让别人拿到可核对的同一份代码

你在本地调好了一个算法，准备交给别人使用。发一个文件夹能把代码传过去，但一个月后再问「你装的是哪一份」，往往只剩一个文件名。仓库分支可能已经前进，同名压缩包也可能装着不同内容。

**算法包（Pack）**把算法代码与描述包及其使用方式的 **manifest（配置声明）**放在一起。算法包站点为发布后的 Pack 提供固定引用，以及接收者核对内容所需的信息。你交出去的是一个确切版本，别人不必靠猜测还原你的工作目录。

## 在站点找到版本，在本地安装使用

`https://packs.xenotech.studio/` 是一个**注册表**，也就是保存包归档和版本元数据的包仓库。发布者上传包，使用者查询版本，再下载对应归档。

站点不是运行平台。下载 Pack 不会执行算法，也不会替你准备运行依赖。本地安装器负责验证并放置文件，实际执行仍由你运行 HoloLab 的环境承担。

站点不做账号体系，没有注册、登录或获取 token 的 API。公开读取无需凭据；发布需要 **Bearer token**，即服务方另行发给可信发布者的访问凭据，并且必须具备目标作用域的发布权限。

## 用包身份告诉别人到底装哪一版

**包身份**用 `scope/name@version` 唯一指向一个发布版本。例如，`example/normalize@1.0.0` 表示 `example` 命名空间下 `normalize` 包的 `1.0.0` 版。这里的名字仅作示例，不表示站点已有这个包，也不表示你已获准使用该作用域。

版本必须写成精确的三段数字，注册表不会替你选择「最新」，也不解析版本范围。工作流记录包身份和预期代码哈希，本地源配置决定去哪里获取。配置源时使用站点根地址，不是 `/simple/`。获取地址改变，不应要求重写包身份。

**不可变版本**是发布 API 的约束：已经发布的同名同版本不能被再次上传覆盖，撤回推荐后也一样。修改内容需要新版本号。这不等于下载字节绝对无法被篡改，接收者仍要核验内容。

**Yank** 是将版本标为不适合新安装的操作，不会删除元数据或归档。客户端必须拒绝新安装被 yank 的版本；已有引用仍然可以解析。发布者可以通过 `unyank` 恢复允许新安装，但这两个操作都不会释放版本号供重新发布。

## 压缩包和代码，要分别核对

**哈希**是从内容计算出来的摘要，用来与预期值比较。注册表记录的两个 SHA-256 哈希各有用途：

| 字段 | 核对什么 | 谁负责验证 |
| --- | --- | --- |
| `archive_sha256` | `.tgz` 压缩文件的完整字节，包括归档元信息 | 服务端上传时验证，客户端下载时重新计算 |
| `code_sha256` | HoloLab 声明范围内的代码身份，按 FORMAT=2 从 manifest 语义和纳入范围的文件内容计算 | 安装器安全解包后重算，与版本记录及工作流的预期哈希比对 |

即使代码没有变化，重新打包也可能改变归档哈希。因此，核对压缩包不能代替核对代码身份。服务端只记录发布者声明的 `code_sha256`，不会重算；仅相信元数据还不能独立证明代码一致。

要确认拿到的是预期代码，应随工作流保存可信的预期 `code_sha256`，先核对版本记录，再独立验证下载归档和解包后的代码。哈希不一致就停止，不能静默换源，直到碰到一个能装上的包。哈希一致说明声明范围内的内容身份一致，不保证算法安全、外部依赖都已固定，也不保证数值结果完全相同。

## 从发布一个包到别人用上它

假设你要分享 `example/normalize@1.0.0`，最小的完整路径如下：

1. **准备版本。** 还没有 Pack 时，先按[编写 Pack](/docs/build/writing-a-pack)准备。设置 manifest 的包名和精确版本，生成 `.tgz`，按 [API 参考](registry-api.md)的规则计算两类哈希，并向服务方取得实际作用域的发布权限。
2. **发布包。** 携带发布凭据，把元数据和归档提交到 `POST /publish`。同时提供 `Idempotency-Key`（幂等键），用这个唯一操作标识让完全相同的请求可以重试而不重复发布。超时不代表发布失败，应按 API 契约用相同键重试原请求。
3. **交出引用。** 把精确包身份、通过可信渠道传递的预期代码哈希，以及用于本地配置的公开源根地址交给接收者。对方读取包不需要 token。
4. **取得指定版本。** 接收者查询 `GET /simple/example/normalize/`，只选择 `example/normalize@1.0.0`，核对身份和预期哈希，并拒绝被 yank 的版本。下载地址使用版本记录 `Release.archive` 中的路径，相对于源根地址解析。
5. **验证后使用。** 安装器检查归档大小与哈希，安全解包，验证 manifest，再从实际文件重算代码哈希。全部通过后才放入本地安装位置，并保存来源、版本元数据和验证记录。运行环境准备与执行是后续独立步骤。

这是发布者和安装器需要完成的协议路径，不表示站点已经提供一键操作流程。下一篇[算法包注册表 API 参考](registry-api.md)给出了请求字段、重试规则和完整的安装验证算法。

## 先了解当前站点的边界

当前所有读取都公开，没有私有作用域，也没有删除版本的接口。作用域用于命名，不是隐私边界；取得发布权限不会让包变成私有包。要阻止新安装，使用 yank；要修正内容，发布新版本。

站点也没有搜索 API，不自动解析版本范围。包名目录和精确版本元数据负责发现与获取，本地安装、运行依赖和执行分别由使用端处理。请以本章节和 API 参考作为当前公开契约；较早的开发者设计讨论可能包含超出当前能力的计划。
