# 节点环境映射热加载

`config.yaml` 的 `envs` 是逻辑环境名到本机环境路径的映射，不属于包身份。
已加载本功能代码的节点支持以下正式入口，均采用同一配置应用流程：

- `hololab pack setup` 写入的新映射、普通 YAML 编辑和原子替换，由配置 watcher 自动采用。
- `POST /api/packs/reload?node_id=<node_id>` 会先重新读取配置，再扫描包。
- `PATCH /api/nodes/<node_id>/config`，请求例如
  `{"patch":{"envs":{"ftgspp":"/absolute/prefix","existing":"/existing/prefix"}}}`。
  `envs` 为整个映射的替换；需保留的键须一并提供。`{}` 清空，省略 `envs` 保留原值。
  PATCH 从磁盘最新配置合并，保留 setup 已写入的映射及尚未生效的重启字段；
  API 与 watcher 在节点内串行应用。外部 YAML 编辑与 API 写入仍应避免同时操作同一字段。

节点先验证完整候选配置，错误类型、空名称/空路径或无效 YAML 不覆盖原有效映射。
路径是否存在、解释器及依赖是否可用由能力检查报告；保存映射不等于安装环境或算法可运行。
GET 配置返回实际生效的 `envs`，`restart_required_fields` 不再包含 `envs`。

映射改变后立即更新网关库存、清除旧能力报告及受影响路径的激活缓存，后台重新检查能力。
配置 API 返回不等待耗时探测；能力接口仍按当前映射解析，不会把待检查状态当成通过。
未缓存的新环境通过原有 `conda run -p` 路径启动，因此无需重启才能解析新映射；
未变环境的激活缓存继续保留。已经确定环境的任务保留配置和激活环境快照，
包括等待执行槽位的任务，其后续校验与启动均使用原环境；新任务使用新映射。
热加载不会安装/删除环境，也不会停止进程。此保证不涵盖外部删除或修改环境本身。

部署本功能仍需让旧进程首次加载新 Python 代码；配置热加载不能替换旧进程中的函数。
升级后不需要为后续 `envs` 增删改再次重启。旧版进程仍遵循其原行为。

测试使用两套临时无 pip 的真实 venv，以及只负责参数转发与 PATH 激活的 conda 替身；
验证真实解释器探测、子进程跨映射切换、watcher/手动 reload/PATCH 和错误回滚。
这不是 FTGSPP GPU 或训练验收。
